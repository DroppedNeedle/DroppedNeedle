# Your library

How DroppedNeedle scans your music, works out which album and edition each folder is, and lets you fix its grouping. Scanning and identification never rename or retag a file. Writing tags and filing music is [Library Management](library-management.md).

## Browsing

The Albums, Artists and Tracks lists show the first page and add the next with Load more, however large the library. Tracks sort by date added, title, artist (then album and track number) or album. Shuffle on the Tracks page plays every track once in a random order.

## Scanning

Scans live on the Scanning tab of Library Management. A running scan can be paused, resumed or stopped there; stopping keeps everything it already read. New music shows up in the library as the scan finds it, not only when the scan ends. Rescan files rereads every file in the folders you pick, even ones that look unchanged, which helps after you fix files with another tool. Each finished run in Recent runs lists the files it could not read or skipped, each with a short reason and what to do about it (for example, a damaged file says to re-download or replace it). If someone changed the library folders since you opened the page, the scan is refused: reload and try again.

After a scan, the library notes which tracks carry lyrics (a lyrics tag, or a `.lrc` file named like the track); it only reads them.

Recent runs can also export a diagnostic report for a scan: a small JSON file with the run's counters, timings, scopes and failed files, to attach to a bug report. Paths are replaced by fingerprints, and it holds no user names, passwords or error text.

MusicBrainz lookups pace at 1 request per second on the official MusicBrainz server. Built-in BrainzMash runs its own local pacing instead. Either way, later scans are incremental, so the first one is the slow one.

## How an album is identified

When most of its files carry a MusicBrainz release ID (Picard and beets write one), DroppedNeedle looks that release up and checks every track against it. Otherwise it searches by album and artist and fetches the best few releases. When nothing turns up, it searches again: without edition and disc words ("Deluxe", "CD1"), then on the title's words in any order, then by the first track's title and the artist. An album filed under "Unknown Artist" is searched under the artist most of its tracks name. Once it knows which album it is, it also lists every edition of that album and checks the ones that could hold your files, so the right pressing is weighed even when search missed it. Each file is paired with a track by title, track number and length. A track MusicBrainz titles as a piece and its movements ("Close to the Edge: I. The Solid Time of Change / ...") also pairs with a file titled with the piece alone, and artists joined differently ("A; B" and "A & B") count as the same credit. An album may hold one file the release doesn't list (two from 21 files on), or, when every track of the release has its file, one for every four paired files; more sends the album to review. When a file's MusicBrainz release ID and recording ID both point to the release but its track ID belongs to another edition (common in downloaded files), the track ID is treated as a tagging mistake, as Picard does: the file is matched by its recording, the edition screen and the file's row on the album page say so, and the right ID is written when the edition's tags are, by writing the edition's tags from the album page or by a Library Management profile that replaces MusicBrainz IDs (both presets do; one that keeps existing values leaves the old ID).

If MusicBrainz has merged a recording since your files were tagged, a file's old recording ID counts as the recording it was merged into. DroppedNeedle asks MusicBrainz about every recording ID none of the candidate releases carries, up to 100 per album. It keeps an answer for a week, and a "no such recording" answer for 10 minutes. A recording ID tag that is not a MusicBrainz ID is not looked up and counts against every release. Downloads being imported are checked the same way.

When every file's tags name the same MusicBrainz release group, or the album is matched to a release group without an edition yet, the album is matched with that group in mind. If the files also name a release that has since moved to another group, the release's group counts. Without a release to look up, that group's editions are checked first; a group MusicBrainz merged counts as the group it was merged into, and one it no longer has is ignored. A release of that group wins a close call with a release of another group, such as one file of an album against the single of the same name. A release of another group that fits clearly better is only applied as a best guess, marked unconfirmed, and it stays unconfirmed until you confirm it or the files' tags name its group. A close call won this way can be undone like any automatic edition ([Library Management](library-management.md#undoing-an-automatic-edition)), and so can a guess that replaced a match with no edition.

Between editions that fit equally well it looks at the barcode, catalog number, media, country and disc count your tags carry (a catalog number of "[none]", as Picard writes for a release without one, counts as none), then at how closely the exact track lengths agree (a remaster or a digital release is often a second or two off the CD), then at your edition preferences.

An album matched by itself moves to another edition of the same album when it is identified again and the barcode or catalog number on more than half its files names that edition, while the edition it has states a different one. The new edition must fit your files as well as any confirmed match must, and must not contradict more of their media, country and disc count than the old one. A MusicBrainz release ID in the files wins: if any file carries a release ID that may be of that album, it keeps its edition. Media or country alone never move an album, and an edition someone chose, a custom edition or one carried over from v2 as chosen never moves. The album page shows the new edition, and an admin can undo the move like any automatic edition ([Library Management](library-management.md#undoing-an-automatic-edition)); an album whose automatic edition was undone is not moved again. Under Library Management, the new edition's tags may be written to the files, and a folder named from the release date may be renamed after the reissue's date. After the upgrade, each album matched by itself this way is checked once, in the background, once its files' edition tags have been read.

Fingerprinting stays off until you add an AcoustID API key (Settings > Library). The key lets DroppedNeedle identify untagged music by its audio and check downloads are the songs you asked for. With a key, only albums whose tags don't match well get fingerprinted, twenty files per AcoustID request. A fingerprint helps a track match when AcoustID hears that track's recording. It counts against a match only when what AcoustID heard is another candidate's track; a recording none of the candidates has says nothing, since AcoustID links many reissues and remasters to no recording or to an older one. Audio alone never moves a file off a track whose title clearly matches it when the track number or length fits too. A title still clearly matches with an addition in brackets or a "feat." credit ("Song (Remaster)", "Song (LP Version)", "Song (feat. X)" match "Song"), unless another track of the release matches it better, such as "Song (Remix)". The album is then left as a best guess for you to check, with a note that the audio and the titles disagree. One case settles itself: when the file's length, measured from its audio, is within 3 seconds of its own track and more than 3 seconds off every track AcoustID heard, the fingerprint is set aside and the album can be matched as if the file had none. The candidate's track evidence shows `acoustid_overruled` for that file.

An edition someone chose is never changed by identification, a rescan or a move. Editions carried over from v2 count as chosen: the custom editions and the pinned editions v2 had. The one exception is the cleanup's fold of an album v2 split in two (below), which drops the v2 match of the half it folds and can be undone from the album's history. Matches identification made, and those v2 took from the files' tags, stay open: a later pass may replace them, and new evidence that contradicts one takes it off. Undo on the album page puts a match taken off this way back; it may be taken off again if the files change. If an album's files change while it is being identified, nothing is applied and the album is identified again on its new files.

Identification has its own Pause button on the Scanning tab of Library Management. The album being identified finishes, nothing new starts until you press Resume, and new scans keep queueing albums in the meantime.

## Unconfirmed matches

DroppedNeedle always picks. A clear match is applied. Files that make up a whole release, every track a close fit and the album title and artist agreeing, are a clear match even without MusicBrainz IDs in their tags, so a one-track single confirms on its own. When the files fit two releases about equally well, such as a single and the album of the same name, the one they make up whole wins. A file only completes a release when its song title matches in full, so "Sunrise" never confirms as "Sunrise (Instrumental)". When the files make up two releases equally well and one is an official release while the other exists only as a promotional copy, the official one wins. Unless every file carries its MusicBrainz track ID, a live album, or a compilation whose tags don't say it is one, confirms only when no other release group comes close and the files fit it almost exactly: every track there, every song title matching in full, every length known and within 3 seconds. If another release of the same live album could be a different night's recording of those songs, the album only confirms when a length more than 3 seconds off rules that other release out. A close call, a loose match, or a live or compilation release that fits less closely gets the best guess applied too, marked "unconfirmed": pages, playback, other apps and downloads use it, but tagging and organizing leave its files alone until you confirm it (or turn on "Also manage unconfirmed matches" in Settings > Editions). A later scan or a verified whole-album download can confirm it on its own. When MusicBrainz can't give a readable copy of the release your files name, the album gets its best-guess edition, marked unconfirmed; when a release it couldn't read leaves nothing that fits, the album waits and is tried again later instead of being marked "no match". Only when every candidate is ruled out does the album keep its own tags, marked "no match", with the closest candidates one click away. Library > Unconfirmed matches lists both kinds; nothing waits on you.

A few cases do wait on a person: an undone automatic edition with nothing to go back to, or editions dropped when two albums were combined. Those sit under Unconfirmed matches > Needs a decision. For each one you can use one of the listed releases, keep the album as tagged, take its MusicBrainz match off, close the review without deciding, start identification again, or (admins) take the album out of the library and put it back later. Nothing is deleted from disk. Starting identification again settles the album the way a scan does: a clear match is applied, otherwise the best guess, marked unconfirmed. If someone chose the album's edition, it keeps that edition and a retry is refused; change the edition on the album page instead. A retry is also refused for an album in a folder set to keep its own tags when Library Management is on for that folder.

Filter the list by folder, folder policy, identification state or filing date, tick several reviews (or every match of the filter) to keep them as tagged, use each one's best release, or take them out in one go: you see what will change and what will be left alone before anything is applied. Retry identification on the Library page can be limited to chosen folders. When you approve an edition, DroppedNeedle matches the files to it in the background, as when you choose one on the album page; until that is done the album's files can't be previewed.

## Album organization

When DroppedNeedle groups files into albums wrongly, an admin can fix it from "Album organization" on the album page. Split takes the tracks you tick and makes them a new album (you can name it). Merge folds the whole album into another one you pick. Move puts the tracks you tick on another album. Reset grouping hands an album's tracks back to automatic grouping, which undoes a split, merge or move. A new album a reset makes is credited to the artist record a scan of its files would give it. Each one shows a preview first: where every track goes, which albums are left empty, and what happens to each album's edition. Nothing changes until you apply, and if the albums changed in the meantime (a scan ran, someone else edited them) or the preview is more than 15 minutes old, you're asked to preview again. These only change how the library groups your files: no file is moved, renamed or retagged. Later scans keep your grouping. An album left empty folds into the one its tracks went to, so its old links, favorites and playlists still work. Player apps that saved the old album or artist find it too.

Editions follow the album they belong to. An album that keeps its tracks keeps its edition. When an album is emptied into another one that has no edition, its edition moves across. When the albums being combined were matched to different editions, an edition someone chose (or v2 carried over) wins against one identification picked; otherwise you choose whether the receiving album keeps its own or all of them are dropped and the album is identified again; if the receiving album has none and several are on offer, they are all dropped. A dropped edition always comes with a short reason on the album. When an album with an edition someone chose gains tracks, by a merge, a move or a retag DroppedNeedle follows, they are matched to that edition in the background; the edition, who chose it and "leave unmanaged" stay as they were.

After an upgrade from v2, a one-time cleanup tidies album rows the old version left behind: empty album shells are folded into the album they name, and albums that an imported match split away from their siblings in the same folder are put back together. That fold happens only when every file of the split half is tagged with the other album's release; it is listed under "Album history" on the album page, where a curator can undo it ([Library Management](library-management.md#undoing-a-split-album-fold)). An album the old version left on "Unknown Artist" while its files name the artist takes the artist its tracks are credited to, and is looked up on MusicBrainz again if it had no match. That change is listed under "Album history" too, and a curator can undo it there while the album's artist is still the one it took: the album goes back to "Unknown Artist" and its earlier credits, and the cleanup leaves it there from then on. The same cleanup runs after each scan, finished or not, for the albums that scan touched and the albums it left empty, and after identification finishes with an album. It works in short steps and never while a scan runs. Only the catalog changes, never your files. Artists the old version linked to MusicBrainz keep their link until it is checked again. The upgrade carries each album's match but not the MusicBrainz release details behind it, so the app fetches those in the background while identification has nothing queued, a few at a time, and then checks each artist link against its album's release: a link the release confirms stays, and one it doesn't is removed or replaced. An album whose release MusicBrainz no longer has is identified again, the app stops asking for that release, and its artists keep their links meanwhile. v2 never stored the edition details your tags carry (barcode, catalog number, media, country, disc count, release date), so the first scan after the upgrade reads just those from each file it finds unchanged; nothing else about the track changes. An album among them that has no match, or only a release group or a best guess, is looked up again when its files carry a barcode, catalog number, media, country or more than one disc, the details matching uses; an album a person detached or whose suggestions they turned down is left alone.

v2 matched some albums to a release group without choosing an edition in it. Tagging and organizing need an exact edition, so the album page shows "Edition not chosen yet" for these. After the upgrade, each one v2 matched by itself is identified once more, in the background and only once: it gets the edition its files fit, or a best guess marked unconfirmed, and the automatic choice can be undone from the album page like any other. If nothing fits, it keeps its release group and still reads "Edition not chosen yet". An album whose release group a person chose, in v3 or in v2, keeps it as it is, and albums in folders that keep their own tags are skipped.

Matching now reads the release group your files' tags name. After the upgrade, an album the app matched by itself before that, on a release outside the one group all its files name, is identified once more, in the background and only once. It usually comes back as a best guess marked unconfirmed: "Fits best, but the files' tags or earlier match name another album." Albums a person matched or detached, or whose suggestions they turned down, custom editions, and albums in folders that keep their own tags are left alone.

## Duplicate artists

Duplicate artists can be merged from the artist identity page (admins). The preview counts what moves to the artist you keep: album and track credits, the albums it is the main artist of, favorites and play history. Ratings move too. The merged artist's old links lead to the one you keep. As in earlier versions, merging artists can't be undone.

DroppedNeedle also merges two records by itself when MusicBrainz proves they are one artist: every credit of the record that goes is on an album matched to a release crediting that artist, or in a file carrying that artist's ID. A track your files credit to the album's artist alone, where the release credits that artist with guests ("feat.", "&"), counts as crediting that artist. When a retag moves an artist's credits to a new record (a changed sort name, for example), the old record follows them once nothing is left on it, even when a large retag is read in several steps: it merges into the new one, taking its favorites and plays, as long as the album match that proved the credits still stands, unless a play is of a track now credited to someone else or MusicBrainz proves the new record is another artist. Records marked as different people are never merged, and one such pair keeps a whole group of records apart. MusicBrainz's special-purpose artists ("[unknown]", "[anonymous]", "[traditional]" and the like) are never proof: files tagged with one are grouped by name, as if they carried no ID. These merges show as resolved in the duplicate artists list, with what each one rested on, and can't be undone either. When a person chooses or confirms an album's edition, approves a review, or imports an album, its artists are linked and merged right after the change is saved, so they are in place when the page answers; if that step fails, the background check does it shortly after.

A retag with no MusicBrainz IDs or match behind it is handled by name. When a scan moves every song of an artist record to one other record, and the two names differ only in sort name, capitals or spacing, the old record merges into the new one at the end of the scan, with its favorites, ratings and plays. Its old ID keeps opening the artist, and the merge shows as resolved in the duplicate artists list. This doesn't happen when the old record is linked to MusicBrainz, when the files carried MusicBrainz artist IDs, when some of its songs went elsewhere, or when a play is of a track now credited to someone else. A larger name change, even a single accent, is never merged by name. In those cases, if the old record holds favorites, ratings or plays, the duplicate artists list offers it with the records its songs went to, so an admin can merge them or mark them as different people. A record offered this way can also appear in that list's group for the new record's own name. A retag of a whole library is settled in one step at the end of the scan, so that step can take a while.

## Removing albums and tracks

Removing an album or a track never deletes your music. The files move into a recycle bin: the recycle bin path in the download settings, or a `.recycle` folder at the top of the library folder the files came from. Each file gets its own dated folder inside it. While the files are there, the album's page lists the removal under "In the recycle bin" for curators and admins (when, how many files), and "Put back" returns them: each track is listed again under its own id, on its album, with its plays, favorites and ratings, and the files come back with their permission bits and modified time. This covers removing a whole album, one track, and files not on the edition, including removals made by Discover batches. Put back never replaces a file that has since taken one of their places, names any file whose copy has left the bin or changed there and puts the rest back, and is finished or undone on restart if it stops part way. A removal whose copies the retention has deleted is not offered. If you got the album again while it was out and the new files landed at other paths, putting the old ones back lists those tracks twice; remove the copy you don't want. If they landed at the same paths, Put back refuses because another file sits where a removed file was, and the old files stay in the recycle bin until the retention removes them. A file the duplicates tools sent to the bin is offered on the album it belonged to; when that album has no files left, no page may lead there, and it is put back from the Recycle Bin page. A recycle bin path that is, holds or sits inside a library folder (other than that folder's own `.recycle`), or that overlaps the download staging folder or SABnzbd's completed-downloads folder, is not used: files go to each library folder's `.recycle` instead, and the download settings show a warning. A bin path that is a symlink works; the checks look at the folder it points to. A library folder's `.recycle` that is a symlink into a library or download folder is not used: removals from that folder are refused and say why, and upgrades there are held, until it is fixed. While the download or SABnzbd settings can't be read, removals and upgrades wait rather than pick another bin. Files in either kind of bin are deleted once they are older than the recycle retention (30 days by default). Admins see everything in the bin under Recycle Bin in the sidebar: each removal, or each set of files an upgrade replaced, with its album, how many files, their size, when it was removed and how many days are left. Removals have "Put back" there too; replaced files can only be moved back by hand. "Empty recycle bin" deletes the files now instead of waiting, under the same rules as the retention, after a confirm that says how many files and how much space. It deletes only what was in the bin when the confirm opened, and older dated folders from before the app kept track of them. It runs in the background and the page says what it did; a run that stops is tried again, and the page says when it gave up. A file is kept if it changed while in the bin, if its bin is no longer the one set, or if it is reached through a link. A bin that is, or holds, a library or download folder is never emptied, and nothing is counted as gone while a bin folder is empty (it may be a share that isn't mounted). Removing an album also stops its failed downloads from retrying, drops its held "couldn't verify" files and its blocklist, and stops its wanted watch unless you untick that in the dialog, in which case it starts looking for a replacement. Putting the album back does not undo that: the held files and the blocklist are gone, a stopped watch stays stopped, and a watch that was looking for a replacement settles by itself once it sees the album in the library. A download it already started keeps going; cancel it on the Downloads page if you don't want it. If any file can't be moved, or a file changes while it is being removed, nothing is removed and the page says why. A removal that stops part way (a crash, a full disk) is finished or put back on restart, never left half done. When the recycle bin can't take a file right away, the file waits under a hidden name beside where it was and moves in by itself once it can. Files in the included subfolders of an excluded library folder can be removed too. A library folder whose path goes through a symlink works like any other; links inside it are never followed. A folder reached through a link whose real path is, holds or sits inside another library folder takes no file changes, and the server log says which. A library folder that isn't there (a drive or share not mounted, or a link to nothing) takes no downloads or file changes until it is back: removals are refused and say why, and changes left unfinished by a restart wait for it. Rescan on an album page rereads just that album's folders. If an album was excluded from file organization, "Manage it again" on its page lets management touch it again.

## Albums with no files

An album marked "No files" has none of its files in the library now: they are missing from disk, in the recycle bin ("Put back" on its page returns them), or excluded. It stays in the web app's album lists and on its artist's page, with nothing to play. Player apps don't show it. Search, Discover and follows treat it as not in your library, so you can request it again.

## Downloading from the library

You can download a single track or a whole album from the library. A track comes as the original file. An album comes as a zip of its files, untouched and uncompressed, and starts downloading straight away, so even a big box set doesn't keep you waiting while the server packs it. Only files the library has scanned, sitting inside one of your library folders, can be downloaded. By default every signed-in user can download; to keep it to trusted users and admins, or admins only, change "Library downloads" under Settings > Security. Streaming is never limited by this setting. The setting is enforced in the web app and on the download addresses of both player-app APIs (Subsonic `download`, Jellyfin `/Items/{id}/Download`), and a player app is told whether its user may download. A player app that saves music through the same address it plays from is not stopped, because the server cannot tell saving from playing. So in player apps the setting holds for apps that use the download address and honour what they are told. It is not a guarantee.

## Lyrics

The web player and player apps show lyrics for a track. Lyrics your files carry come first: a `.lrc` file next to the track with the same name, else the file's lyrics tag. Jellyfin apps such as Finamp only offer lyrics for those tracks. When a file has none, the server asks LRCLIB ([lrclib.net](https://lrclib.net)), a free lyrics database, at the moment lyrics are opened, sending the track's title, artist, album and length. LRCLIB's answer is remembered for a while (a week when it has lyrics, six hours when it has none), so opening the same track again does not ask again. Nothing is written to your files. This is on unless an admin turns it off under Settings > Library > Lyrics; while it is off, the web player and player apps never ask LRCLIB. Library Management fetching lyrics into files has its own setting.

## Ratings

You can give an album 1 to 5 stars on its page, and each of its tracks that has a file in your library. An artist in your library can be rated on the artist's page. Clicking the star you gave clears the rating.

Ratings are kept per account, and they are the same ratings Subsonic apps show and set: a rating given in either place shows in the other. In a Subsonic app, setting 0 stars clears your rating. Subsonic apps also show the average of every user's rating of an item; on a server with few users, that average can give your rating away. The web app shows only your own.

The "highest rated" album list in Subsonic apps shows the albums you rated, best first. When albums, artists or tracks are merged, their ratings move to the one that stays; if you rated both, the one that stays keeps its rating. Jellyfin apps don't show ratings.

## Adding a missing album to MusicBrainz

When an album in your library isn't on MusicBrainz yet, an admin or trusted user can add it from the album page with "Contribute to MusicBrainz". DroppedNeedle never edits MusicBrainz for you; it fills in the MusicBrainz release editor and you check and submit it there, under your own MusicBrainz account.

1. Start the contribution. The draft is built from your files: title, artist, tracklist and lengths. Fix anything that's wrong; every value you change is marked as entered by you.
2. Optionally pick the matching Discogs release. Its label, catalogue number, barcode and country can fill the draft, and the Discogs link goes along as a source. Discogs data is only shown for six hours, then you select the release again to refresh it.
3. Run the duplicate check. If MusicBrainz already has the release, link to it instead and you're done. If it only has similar releases, confirm they are different editions.
4. Open the MusicBrainz editor, review and save the release there. MusicBrainz sends you back to DroppedNeedle, which checks the new release in the background (new releases can take a few minutes to show up) and then links the album to it.

If the check can't link the album, the contribution says why and what to do next, and you can retry or enter the release link by hand. If your files change while a contribution is open, rebuild it from the album's current files.

MusicBrainz sends you back to the address your browser used to reach DroppedNeedle, so this works behind a reverse proxy and under `BASE_PATH` without extra setup.
