# Requests and downloads

What happens between pressing Request and the album landing in your library, and what you can do when it does not go to plan. Setting up slskd and SABnzbd is in the [README](../README.md#download-sources).

## Which edition is fetched

Downloads follow the edition you chose. If the album is already in your library, a request, an "acquire this edition", or an upgrade fetches the album's edition: the one you picked, else the one that best fits your files. For an album you don't have yet, it fetches the edition the album page showed you, which follows your edition preferences (Settings > Editions). Admins and trusted users can choose another one first: the album page shows the edition it will get, and Change opens the list of editions with each one's tracks. Pick one, then Add to Library. You can switch a request to another edition the same way until its download starts; after that the page shows which edition is downloading. Candidates are ranked against that edition's tracklist: first by how many of its tracks a folder holds, then by how close the track lengths are, then by quality, then by speed.

## Single tracks

A single track is fetched the way you would do it by hand. DroppedNeedle looks up which album the track is on (the edition you chose for it if you own that album, else the release you asked from, else the main official album rather than a compilation or a live set), searches for that album, picks the peer sharing the most complete album folder, and downloads only the track you asked for. The file is then checked against that album's tracklist. A peer sharing just the one song is only used when nobody shares the album with it; when that happens the download records why. On Usenet, which can't download single files, the album release is fetched and only your track is imported.

Some songs are on a single that nobody shares, while the album with the same song is everywhere. When the only copy that turns up is the album's track, the download stops at once instead of trying other sources, the file is held, and the request reads "Only the album version was found". Press "Get it from the album" on the request to fetch that track again and import it as the song you asked for; the held copy is then cleared from Held files. It is only taken when it is the same song: same artist, same title and about the same length as your single's track. The album version can differ from the single (a different mix or edit), so this is your call, not the app's.

Every finished download is checked before it touches the library: the files must be readable audio of the right album and edition, inside your quality range, and match a release of the album you asked for track by track. Files that pass are tagged (unless their folder keeps its own tags), named by your [import naming script](#import-naming-script) and filed in the library. Files that don't fit well enough are held for you to look at, and bad sources get quarantined so they stop winning.

## Following artists

Follow an artist and DroppedNeedle checks MusicBrainz for their new releases once a day, a few artists at a time and behind your own page loads, so it never crowds MusicBrainz. The first check only remembers what the artist already has. After that, anything new that matches your release types (Settings > Release Types) and that you don't already own shows up under Following > New Releases, with a badge in the sidebar. Turn on auto-download for an artist and new releases are downloaded on their release day: one download per release, even when several people follow the artist, and nothing is fetched if it's already in the library or already downloading. Each download is a request of the follower's, so it shows on their Requests page and counts toward their quota; with the quota full it waits there and starts by itself once there is room. Regular users need an admin to approve auto-download first; trusted users and admins don't. An approval stays until an admin revokes it, so turning auto-download off and on again doesn't need a second one. If MusicBrainz can't be reached, the artist is tried again an hour later.

## When a download finishes

DroppedNeedle reads every file, then checks them. Wrong album or edition (a live album or box set when you asked for the studio album), files outside your quality range, sample clips or unreadable files mean that source is skipped and the next one is tried. Soulseek folders and Usenet releases whose quality the search already shows outside your range are never downloaded on their own; you can still pick one yourself (see [Choosing a copy](#choosing-a-copy)). The rest are matched against the release you asked for, the same way album identification works. With no edition settled, the editions MusicBrainz lists for that album are checked, closest track count first. If the album is already in your library, its edition (for "Get the missing tracks" the edition of that copy, else the one you picked, else the one that best fits your files) is the only one accepted: the files are checked against its tracklist, files tagged as another edition send DroppedNeedle to the next source, and the missing tracks it asks for come from that edition. A close match goes into the first library folder whose policy is Automatic at the path your import naming script gives it (a path rule there counts), with the full MusicBrainz tags written, and shows up in the library and on the request straight away, without waiting for a scan. Tracks you already have are not imported twice, and extra files the release doesn't list (bonus tracks, scene extras) are left out. Where a file lands in a folder set to Local metadata (the whole library folder or a path rule), it keeps the tags it came with: it is placed and matched, but the release's tags are not written. A track fetched for an album there ("Get missing tracks") joins that album's folder and keeps its tags the same way. If no library folder is Automatic at that path, the download goes into your first library folder that is not set to Excluded, and the files whose path there is Local metadata keep the tags they came with; the rest are tagged. A download for an album you already have stays with it: "Get missing tracks", re-requests of that album, upgrades and drop imports don't look for another folder. They go into your first library folder that is not set to Excluded (beside the album's files when they are there), and keep the tags they came with where their path is Local metadata.

Files with no artist tags go in only when something else shows who they are by: a folder or file name below the client's download folder, or a folder in the path the source shared them under, names the artist (the usual "Artist - Album" folder; for a various-artists release, the album title), the files carry their own MusicBrainz ids, AcoustID recognises them (with an AcoustID key set), or the tracklist fits closely (three or more files covering at least 80% of the release's tracks). Otherwise they are held with the reason "The files have no artist tags, and nothing shows they are by this artist." A file whose own artist tag names someone else is held as well when its title or length doesn't fit the track either; a different artist tag alone holds nothing, since classical files often name the composer.

If some files clearly name other songs, sound like a different recording, or the album as a whole is not close enough, those files are copied to the held area for you to look at, that source is skipped, and the next one is tried, asking only for the tracks still missing. The download settles as held or partly imported only once there are no sources left, or straight away when the only thing in the way is on your side (a file already sitting where a track would go), since another source would not help. The exception is a single whose only copy is its album's track: it is held at once and no other source is tried (see [Single tracks](#single-tracks)). A file sounds like a different recording when, with an AcoustID key set, AcoustID hears another recording in it and its length is more than 3 seconds off the track's (copies of one master are rarely further apart).

When a download is an upgrade for an album you already have, a new file replaces your copy of a track only if it is better quality; your old file stays where it is until the new one is in, then goes to the recycle bin, never straight to deletion. If the upgrade stops part way (a restart, a full disk), the old file or the new one is in place afterwards. The one exception: if another program puts a file where your old file was while the upgrade is being undone, your old file is kept under a hidden name beside it and the write is listed under "Some file writes need you" on the Library Management page. If the old file can't be moved to the recycle bin, the new one is held and your copy stays. The new file joins the album the old one was on. In a folder that keeps its own tags, the new file keeps the tags it came with, and your old file, with your tags, goes to the recycle bin. Files that are no better count as already owned: your copy stays and the download's file is not imported. A download with thousands of files is not treated as one album: nothing is imported or copied, and the files stay where they are for you to sort out. Each skip and hold is recorded with a short reason and what you can do about it.

Retry import on a failed download imports the files it left on disk right away, with the same checks, without searching or downloading again. A failed download's files are kept for this for 90 days, then cleaned up. Stopping the download cleans them up straight away. For SABnzbd and plugin downloads that means their folder is removed; for slskd only the transfers are cleared, and the files stay in slskd's download folder.

A download doesn't start while the library folder downloads go to (the first one set to Automatic, else the first one not set to Excluded) is missing (an unmounted share, say), can't be written to or doesn't answer. It stays in the queue as "Waiting: library folder /music isn't there." (or "can't be written to", "isn't answering") and starts by itself once the folder is back. A download that finishes while the folder is gone waits the same way, with its files left where they are, and is imported once the folder is back. Requests are still taken while it waits.

## Import naming script

Downloads and drop imports are filed at the path the import naming script gives them (Settings > Library). It is written in the same naming script language as Library Management, and is read from the tags DroppedNeedle writes, so a Library Management profile with the same script and default path settings never moves an imported file. The default files a track as `Artist/Album (Year)/0103 Title.flac`, with the year left out when the release has none:

```
{albumartist}/{album}{conditional(is_empty(slice(default(original_date, date), 0, 4)), "", concat(" (", slice(default(original_date, date), 0, 4), ")"))}/{disc:02d}{track:02d} {title}.{ext}
```

Text outside braces is kept. `{name}` is a value, such as `albumartist`, `album`, `title`, `track`, `disc`, `ext`, `initial` (the album artist's first letter, past a leading "The") or any tag name, and `{track:02d}` pads a number. Anything else in braces is an expression, such as `default(a, b)`, `conditional(test, then, else)`, `is_empty(x)`, `concat(...)` or `slice(text, start, end)`. Characters a file name can't hold become `_`, and each folder and file name is cut to 240 bytes, keeping the extension. Saving checks the script and shows where it would file an example track. A script that leaves a folder name empty for some album stops that import with the reason "The import naming script gave no usable path": fix the script, then retry the import.

## Held files

Every file that waits for your decision, whether a download or an upload brought it, is in one list on the Downloads page, and on its album's page. One download or one upload is one entry with its files: an album held from two sources is still one entry. Each file says why it was held and what to do, and each entry says how long it is kept ("Kept until 23 Jan").

Every entry offers the same actions:

- **Listen** plays a file to hear whether it's the right song.
- **Import** places the files, skipping the check that held each one, but not the comparison with your copy: a file that isn't better than the copy you have is kept, never deleted, and the page says so. Its button then reads **Use this file**: pressing it replaces your copy, which goes to the recycle bin.
- A held file of a lower-quality version (see [Library management](library-management.md)) offers **Use this version**: it becomes your copy, and yours goes to the recycle bin with its plays, favorites and playlist entries moving to the new file. Both buttons say so before anything moves. If the recycle bin refuses your copy, the file stays held with the same button, so once the bin works one press finishes it.
- Files held because something on the library side was in the way (a file already sitting where a track would go, a library folder that isn't there) show **Retry** instead of Import: the library decides again. DroppedNeedle also retries these by itself, a few minutes after they were held and then at longer gaps, up to once a day, until they go in or the entry expires. The entry shows when the next try is, and "Retrying now" while it runs. A retry that comes back with a reason you decide on, such as a file no better than yours, stops retrying. A retry never adds a second copy of a track you already have on another copy of the album, and never replaces a copy that has since turned up on the album itself: that file waits for you instead.
- **Match** (admins and trusted users) picks the album yourself; DroppedNeedle pairs the files with its tracks. A file that would replace a library copy then needs AcoustID to confirm it: when AcoustID can't answer, the file stays held and your copy stays.
- **Re-check** runs AcoustID again on files it heard as a different recording or could not confirm, and imports those it now confirms. "Re-check all" does this across the list, 25 files at a time.
- **Discard** deletes the held files. For a download, the album's automatic retry picks up again once none of its files is held.
- A single found only as its album's track offers **Get it from the album** (see [Single tracks](#single-tracks)).

An imported file goes where the download would have put it: a track fetched for an album you have ("Get the missing tracks") joins that copy, in its folder and on its edition; otherwise it goes into the edition you chose for the album, and if the track isn't on that edition, the page tells you to pick the edition it belongs to first. An upload's file that was never paired with a track has no Import: Match is the way forward. When importing the last held files makes an album whole, its download shows as completed.

Entries are kept for 90 days after they were made, or after their newest file arrived. After that the held copies are removed: only the copies DroppedNeedle keeps for you in its own folders, never a file in your library or in a download client's folder. An entry you are acting on is never removed under you. If the server stops while an import from the list runs, the files that already went in are marked imported when it starts again, and the rest wait as before.

## Upgrades

With upgrades switched on in the download settings, admins and trusted users see the albums whose worst file is below your quality cutoff and can ask for a better copy of an album or a single track. Asking for one that already meets the cutoff queues nothing. The background upgrade scan, when switched on, works through the same list on its own, under the oldest admin account. It leaves an album alone while files downloaded for it are held for your decision. After an upgrade finishes, the album waits a day before the scan tries it again; each failed or cancelled try in a row doubles that wait, up to 30 days. Changing the quality settings does not reset these waits.

## The Downloads page

The Downloads page updates on its own: progress, new tasks and status changes arrive over the same live connection as the rest of the app, so nothing needs a reload. Every download that failed, was held or landed short shows one short reason and what you can do about it, taken from what the import decided (for example "The files belong to a different album by the same artist"), never a raw error.

On the Downloads page you can cancel a download, retry it, or move a Soulseek download that sits in a slow peer's queue on to the next source. A Soulseek download that has waited in a peer's queue with nothing downloaded for the preferred-quality wait (15 minutes by default, under the advanced download settings) moves on by itself to another peer's copy, unless it is a copy you picked from a search or the download's last allowed attempt. It only moves once the other copy is queued: if no other peer has the album, it keeps its place and looks again after another wait. The slow peer is not blocked. Cancel on a failed download stops its automatic retries and its wanted watch. Retry starts a fresh attempt straight away; for an album it also clears that album's blocked sources, so a source that failed before gets another chance. The bulk buttons clear finished downloads, stop every scheduled retry, or retry every failure that won't retry by itself. Admins see and act on everyone's downloads; everyone else sees their own.

## Choosing a copy

To choose the copy yourself, press "Pick a source" on a failed, cancelled or partial album download. DroppedNeedle asks every download source you have turned on for that album and lists what each one has, grouped by source with the best fit first. Soulseek folders are compared with the tracklist of the edition you asked for, so each one says plainly what it looks like ("Holds all 12 tracks of this edition", "Holds 9 of the 12 tracks", "2 track lengths do not match"). Each copy also shows what it is ranked on: a Soulseek folder its format with the bitrate or bit depth its files report, a Usenet release its indexer, age and grabs, a plugin release the source's own score. Copies outside your download settings (your quality range, the size limit, ignored or required terms, or a plugin score below your minimum) are listed after the rest, each with the reason. Pick one and DroppedNeedle downloads exactly that folder or release, then checks the files like any other download; if it fails, the normal search takes over. Picking a copy outside your settings asks first. Once you confirm, that download is kept even if its quality is outside your range; every other check still runs, and if it fails, the next source is held to your settings as usual. A copy kept below your quality range may later be replaced by the background upgrade scan. "None of these - keep watching" closes the search and puts the album on your wanted list, and the copies you turned down are remembered so they aren't offered as new finds. A search takes up to a couple of minutes, and the results update by themselves when it finishes. If no source is turned on or none of them answers, the search says so and what to check. The wanted watcher re-searches a watched album the same way: it asks only the sources you have turned on, plugin sources included, with the same filters.

Before downloading an album on its own, DroppedNeedle looks at what every source has, the same way "Pick a source" does. If a copy looks like the whole edition in a quality you accept, it downloads that one. If none does, the album waits in the download queue as "Awaiting review" with the copies it found, and you choose one, or press "None of these - keep watching". Nothing is downloaded until you do. You can change this under Settings > Download Client, "Picking a copy": wait only when no copy looks right (the default), always wait for your pick, or never wait and take the best copy found. Single tracks are not held this way; they are fetched from their album's folder as described above.

## Blocked sources

Admins can see blocked sources (Downloads > Quarantine) with the reason each was blocked, and remove one so it can be tried again. Blocks expire on their own after a week.

## Drop imports

Bought music somewhere else? Drop it in. Admins and trusted users can upload up to 25 files at once on the downloads page, 8 GB in all: audio files, or `.zip` archives straight from the store. The drop zone shows how much has been sent. If nothing more gets through for a minute, the upload stops with an error. DroppedNeedle unpacks the archives (audio only), treats each top-level folder as one album, and works out which album it is the way a library scan would: MusicBrainz tags first, then the album and artist names (from the tags, or a folder named `Artist - Album`), then AcoustID fingerprints when you have set an AcoustID key.

- A folder that matches closely is renamed with your import naming script, tagged, and added to the library. Where it lands in a folder set to Local metadata, its files keep the tags they came with, and the import's summary ends "Tags kept as they came." If the album is now complete, its open request and wanted watch are settled and everyone who asked for it is told.
- If your library already keeps an edition of that album, the files must match that edition. Files of another edition wait in [Held files](#held-files) instead of quietly importing as a second edition.
- Tracks you already have are skipped as already owned, unless the upload is better quality and clearly the same song: its tags must match the track closely, and with an AcoustID key set the audio must not be a different recording. After a hand match, AcoustID has to confirm it: when AcoustID can't answer (no key set, or the lookup fails), the upload waits for review and your copy stays. Then it replaces your copy, and the old file goes to the recycle bin once the new one is in. The new file joins the album your old copy was on. If the new file can't be placed, or your copy can't be moved to the recycle bin, your copy stays and the upload waits for review with the reason; it is never deleted. A file that fails these checks waits for review with the reason.
- Extra files that came with the album but aren't on its tracklist (a bonus track MusicBrainz doesn't list) are kept alongside the album under their own title and number. Files whose tags name a track they don't match wait for review on their own.
- Anything DroppedNeedle can't place waits in [Held files](#held-files), shown inside its upload on the Import tab too, with a plain reason and what to do. Pick the album yourself with Match, import files already paired with a track, or Discard to delete them. They are kept for 90 days, like every held file.

If the server restarts in the middle of an import, the upload's files wait in Held files as interrupted; pick the album with Match or drop them in again.

The server log notes each upload when it starts and when it has arrived (its size and file count), and each import when it starts and finishes.

### Behind a reverse proxy

A proxy in front of DroppedNeedle has its own upload limits, and a large zip can hit them before DroppedNeedle sees it. An upload the proxy refuses shows an error naming the proxy; one it holds stalls and stops after a minute.

- nginx accepts 1 MB by default. Set `client_max_body_size 8g;` (or `0` for no limit) in the DroppedNeedle `location`, and raise `client_body_timeout`, `proxy_send_timeout` and `proxy_read_timeout` if your uplink is slow. `proxy_request_buffering off;` passes the upload straight through instead of storing it on the proxy first.
- Cloudflare's proxy takes at most 100 MB per request on the Free and Pro plans. Upload larger zips from your own network, at DroppedNeedle's own address, or split the album into smaller zips.
