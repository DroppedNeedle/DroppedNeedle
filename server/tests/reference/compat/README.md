# Reference answers from real servers

DroppedNeedle emulates the Subsonic and Jellyfin APIs. These folders hold
what a real Navidrome and a real Jellyfin answered for the requests the
supported clients make, so the emulation can be compared with the servers
it stands in for and not only with its own earlier output.

They are recordings, not goldens. Nothing here is regenerated by a test
run, and no file is ever edited by hand.

## What is here

| Path | Holds |
|---|---|
| `library.json` | The six fixture tracks every server was given, and the keys requests use to name them |
| `navidrome-0.62.0/` | Navidrome 0.62.0, requests that only read |
| `navidrome-0.62.0-writes/` | The same server after one star, one playlist and one scrobble |
| `navidrome-0.62.0-arpeggi/` | Navidrome 0.62.0 again, fresh, for Arpeggi's artist browsing: its library sync, the artist list and index, one artist, and music folder 0 |
| `navidrome-0.62.0-ratings/` | Navidrome 0.62.0 again, fresh, after one rating each on a track, an album and an artist |
| `jellyfin-10.10.6/` | Jellyfin 10.10.6, requests that only read |
| `jellyfin-10.10.6-writes/` | The same server after one favourite, one playlist and one play report |
| `jellyfin-10.10.6-lyrics/` | Jellyfin 10.10.6 again, fresh, with a `.lrc` file beside Airbag: the two OK Computer tracks, their album, PlaybackInfo and the lyrics address |
| `jellyfin-10.10.6-played/` | Jellyfin 10.10.6 again, fresh, after marking a track, an album and two artists played, then the track and the album unplayed |
| `jellyfin-10.10.6-paging/` | Jellyfin 10.10.6 again, fresh: album and track pages without `SortBy` that start off a multiple of `Limit`, with and without `EnableTotalRecordCount` |

Each folder has:

- one file per request: the request line, the status, the framing headers
  and the body. Audio and image answers record their length, not their
  bytes.
- `index.json`: the requests in the order they were sent, in a form that
  can be replayed against another server. `{track.airbag}`,
  `{album.ok_computer}` and `{artist.radiohead}` stand for that server's own
  id for the entry with that key in `library.json`. An album is the one
  holding the first track listed for it. `{user}`, `{library}`,
  `{password}` and `{token}` are the caller's, and `{playlist}` is set by
  the request that carries `sets`.
- `capture.json`: the image tag, the image id, the version the server
  reported and the date.
- `SHA256SUMS`: a checksum for every other file in the folder.

A folder ending in `-writes` continues the run of the folder beside it:
its first three requests are the writes, the rest read what they changed.
A folder named for a client, such as `-arpeggi`, is a run of its own on a
fresh server. So is `-ratings`: its first three requests rate a track, an
album and an artist, the rest read them, and its last two clear the
track's rating and read the track again.
`-lyrics` is a fresh server whose library also holds
`fixtures/library/lyrics_airbag.lrc` as `Radiohead/OK Computer/01 Airbag.lrc`;
its `capture.json` names that file under `extra_files`.
`-played` is a fresh server: each mark is followed by the reads that show
it, and its last request marks an unknown id.

## What was removed

The servers were throwaway containers, but their answers still carried
values that mean nothing outside that run:

- The password is `***` and every token is `<token>`.
- Server-made ids are replaced by a number of the same length, counted in
  order of first appearance, so `0000000000000000000008` is the same track
  wherever it shows up. MusicBrainz ids come from the files' tags and are
  kept.
- In timestamps every digit is `0`.
- Hosts are `http://reference.invalid`.

Titles, formats, counts and everything else are as the server sent them.

## Checking

```
cd frontend
pnpm exec node ../server/scripts/compat-reference.mjs check ../server/tests/reference/compat
```

This fails if a file no longer matches its checksum, or if anything that
looks like a token, a password, an IP address or a host path is present.

## Recording another version

A new server version is a new folder. An existing folder is never
replaced: the recorder refuses to write into one.

The recorder is `server/scripts/compat-reference.mjs`. It never starts a
container. It talks only to the loopback address, refuses a server that
already has a user, refuses any version but the one pinned at its top, and
refuses to run in CI. The steps, one server at a time:

1. Pin the new image tag and version at the top of the script.
2. `plant <this folder> <checkout>/dn-ref-tmp` copies the six tracks to
   `dn-ref-tmp/music`. With `--set lyrics` it also copies the set's `.lrc`
   file.
3. Start the server yourself with that folder as its only mount,
   read-only, on a loopback port, with name lookups blocked so it cannot
   fetch artwork or metadata:

   ```
   docker container run --name dn-ref-navidrome --rm -d --hostname dn-ref --dns <loopback> -p <loopback>:14533:4533 -v <checkout>/dn-ref-tmp/music:/music:ro -e ND_MUSICFOLDER=/music -e ND_ENABLEEXTERNALSERVICES=false -e ND_ENABLEINSIGHTSCOLLECTOR=false deluan/navidrome:<tag>
   docker container run --name dn-ref-jellyfin --rm -d --hostname dn-ref --dns <loopback> -p <loopback>:18096:8096 -v <checkout>/dn-ref-tmp/music:/media/music:ro jellyfin/jellyfin:<tag>
   ```

4. `navidrome <this folder> --image-id <id>` or
   `jellyfin <this folder> --image-id <id>`, with the image id from
   `docker container inspect`. The recorder creates the first user, scans,
   records, and writes both folders only when every file has passed the
   scrubbing checks.
5. Stop the container, then `clean <checkout>/dn-ref-tmp`.

A request set of its own (`arpeggi`, `ratings` for Navidrome, `lyrics`,
`played` and `paging` for Jellyfin) is recorded the same way on a fresh
container, with
`navidrome <this folder> --image-id <id> --set <set>` or
`jellyfin <this folder> --image-id <id> --set <set>`. It writes only
`<server>-<version>-<set>/` and refuses if that folder exists. The
`lyrics` set needs the tracks planted with `--set lyrics` too.

The notes beside the setup code in the script say what was confirmed
against each recorded version. Confirm them again for a new one.
