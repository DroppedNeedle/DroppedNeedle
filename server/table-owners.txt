# Who owns each table in the database.
#
# Every table has one owning area, named in brackets above it. The owner
# is the area that writes the table and whose migrations change it; other
# areas may read it. A few tables are still written from more than one
# area, and those writes are moving to the owner.
#
# Writes from outside the owning area that exist today, all by library
# code inside its own transaction, when one album, artist or track row
# takes the place of another (a merge, or a scan following a retagged
# album onto its old row):
#   library_user_favorites        catalog   moved to the surviving row
#   library_user_favorite_names   catalog   moved with their favorite
#   library_user_ratings          catalog   moved to the surviving row; a
#                                           user who rated both keeps the
#                                           surviving row's rating
#   library_play_history          media     moved to the surviving row
#   playlist_tracks               catalog   album_id set to the surviving
#                                           album (a followed retag, or a
#                                           retag joined across two scans)
#
# And when a missing track continues into the track that took its place
# (the same release track of the same album):
#   library_user_favorites        catalog   moved to the track it continues
#   library_user_favorite_names   catalog   moved with their favorite
#   library_user_ratings          catalog   moved to the track it continues
#   library_play_history          media     moved to the track it continues
#   playlist_tracks               catalog   library_file_id and
#                                           track_source_id of local entries
#                                           moved to the track it continues
#   compat_bookmarks              compat    moved to the track it continues
#   library_user_play_marks       catalog   moved to the track it continues;
#                                           a user's marks on both rows
#                                           merge, the later of each time
#   compat_play_queue_items       compat    moved to the track it continues
#
# One more, also by library code in its own transaction: the repair that
# files plays naming no track, album or artist under the one track they
# fit. It fills those three columns of such a row and changes nothing
# else:
#   library_play_history          media     track, album and artist set
#
# Kept by triggers (from migration 0065), not by code: no code writes
# library_user_album_plays. The database rewrites its rows inside the
# transaction of every write to library_play_history,
# library_user_play_marks and local_tracks, whichever area makes it.
# local_albums.has_indexed_track is kept the same way, from local_tracks.
#
# Kept by triggers (from migration 0080), not by code: no code writes
# library_artist_album_credits or library_artist_counts. The database
# rewrites their rows inside the transaction of every write to
# local_track_artists, local_tracks, local_albums, local_album_artists and
# local_artists, whichever area makes it. The partial index
# idx_local_albums_owned_leader on local_albums belongs to that refresh.
#
# Add a table here in the commit that creates it and remove it in the
# commit that drops it: the schema tests fail when this list and the
# migrated schema disagree.
